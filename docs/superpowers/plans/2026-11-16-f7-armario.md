> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development para
> implementar este plano tarefa a tarefa. Os passos usam checkbox (`- [ ]`).

**Goal:** aba nova "Armário" em Estilo & Engenharia — planejar a vitrine do e-commerce arrastando
variantes (produto × cor) para uma grade ordenada por subcoleção, com status rascunho→pronto→publicado.

**Architecture:** 2 tabelas novas (`armarios` + `armario_itens`) com RLS por tenant (molde
`mix_padroes.sql`) + gatilho de trava "publicado"; RPCs DEFINER (leitura compõe 3 origens de variante,
escrita estado-completo com `_seg_exige_pagina`); front com rota nova, lista reordenável (molde
`cadastro.lojas.tsx`) e grade 2D ordenável (`rectSortingStrategy`, 1º uso) + dialog com cross-container drag.

**Tech Stack:** Vite + React + TanStack Router + Supabase (Postgres, RLS, RPC DEFINER); @dnd-kit.

**Spec:** `/Users/sunglee/.claude/plans/h-uma-necessidade-de-flickering-lovelace.md` (brainstorming aprovado).

## Global Constraints

- Migration aplicada SÓ na cópia local (Docker PG17.6 127.0.0.1:54422) nos testes; produção só no deploy.
- RPC: wrapper + `_core` com `REVOKE EXECUTE … FROM PUBLIC, anon, authenticated`; `SET search_path TO 'public'`.
  Escrita leva `_seg_exige_pagina('criacao_armario')`; leitura não (segue RLS).
- RAISE que o PostgREST devolve 5xx = só ASCII. `42501`/`P0001` (403/400) podem ter acento.
- Referência estável da variante = `modelo_id` + `cor_id` + `cor_apelido_id` (+ ponteiro nativo
  `variante_tecido_id`/`produto_variante_id`). NUNCA usar "ordem da variante" como identidade.
  Snapshot de cor derivado no SERVIDOR (não confiado do cliente). FKs de cor/variante NO ACTION.
- Armário vazio é salvável. Reordenar armários NÃO bloqueia por publicado.
- Trava "publicado": imposta no servidor (RPC `FOR UPDATE` + gatilho BEFORE I/U/D), não só UI.
- Estado completo no `armario_salvar` (delete-and-reinsert, ordem=índice 1-based).
- Após mexer em imports rode `npx tsc --noEmit`. `vite build` não faz type-check.
- Subagente de banco: `export DATABASE_URL` da cópia local (fallback = PRODUÇÃO). NUNCA `\i` migration
  em txn de teste. Deploy: banco ANTES do site.
- Branch: `f7/armario`. `git commit --only` (nunca `git add .`).

## Review Focus

- Variante cujo PONTEIRO quebra (cor excluída do produto depois de entrar no armário) → item vira
  "cor removida", não some nem apaga a vitrine (FKs NO ACTION). (Task A1/C1.)
- Mesma variante arrastada 2× no MESMO armário → index único barra (sem erro feio; a UI não duplica). (A1/D4.)
- Armário "publicado" + tentativa de editar item/nome pela API direta → gatilho recusa (42501/P0001 ASCII). (A2.)
- `armario_salvar` com lista VAZIA → aceita (não recusa como a Camada C1). (C2.)
- Nº de colunas mudado → a ordem 1..N dos itens NÃO muda (colunas é visual). (B2/D4.)
