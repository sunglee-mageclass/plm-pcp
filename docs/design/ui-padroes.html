AGuarda de "alterações não salvas" (dirty) — PADRÃO DO SISTEMA

Regra: TODO formulário com botão Salvar usa o guarda compartilhado. Enquanto há edições pendentes, um selo âmbar ("● alterações não salvas") aparece INLINE no header da própria tela, alinhado à direita (acima da linha separadora), via <UnsavedIndicator show={dirty} className="ml-auto shrink-0" />. NÃO é mais flutuante/global (não sobrepõe relógio/botões). Ao fechar (X, ESC, clicar fora, Cancelar/Voltar) — ou, em página inteira, ao navegar para fora — com pendências, o <UnsavedChangesGuard> mostra um AlertDialog: Descartar alterações? → Continuar editando / Descartar.
Exemplo
● alterações não salvas — inline no header, à direita
Descartar alterações?
Código

  useUnsavedGuard({ dirty, onClose: () => setOpen(false) });

<Dialog open={open}
  onOpenChange={(o) => { if (!o) requestClose(); }}>
  <DialogHeader><div className="flex items-center gap-2">
    <DialogTitle>Editar…</DialogTitle>
    <UnsavedIndicator show={dirty} className="ml-auto shrink-0" />
  </div></DialogHeader>
  …
  <Button variant="outline" onClick={requestClose}><ArrowLeft/> Voltar</Button>
</Dialog>
<UnsavedChangesGuard confirm={confirm}
  message="Há alterações não salvas neste cadastro." />

// Formulário grande / async — Caso C

// reset(next) ao semear (query/abrir-editar); markClean() no onSuccess

// Página inteira — bloqueia navegação

// OC: OcModalShell já guarda — só passe dirty:
<OcModalShell isEdit onClose={…} dirty={dirty}
  discardMessage="Há alterações não salvas nesta OC." />

Fora de escopo: confirmações puras ("Excluir?", "Salvar mesmo assim") e pickers cujo botão principal é "Aplicar"/"Confirmar". BBreadcrumb de contexto "Módulo › Tela › Entidade"

Quando usar: no topo de uma tela de detalhe/Sheet, para ancorar o usuário. Texto muted-foreground; a entidade atual em foreground e negrito. Ainda não existe componente — proposta: criar src/components/shared/Breadcrumb.tsx.
Exemplo
Estilo & Engenharia› Plan. Tecido› Coleção Verão 26
Código (componente proposto)
// src/components/shared/Breadcrumb.tsx
import { ChevronRight } from "lucide-react";

type Crumb = { label: string; href?: string };

export function Breadcrumb({ items }: { items: Crumb[] }) {
  return (
    <nav className="flex items-center flex-wrap gap-1.5
                    text-sm text-muted-foreground">
      {items.map((c, i) => {
        const last = i === items.length - 1;
        return (
          <span key={i} className="flex items-center gap-1.5">
            {i > 0 && (
              <ChevronRight className="h-3.5 w-3.5 opacity-50" />
            )}
            <span className={last
              ? "text-foreground font-semibold"
              : ""}>{c.label}</span>
          </span>
        );
      })}
    </nav>
  );
}

// uso
<Breadcrumb items={[
  { label: "Estilo & Engenharia" },
  { label: "Plan. Tecido" },
  { label: "Coleção Verão 26" },
]} />

// src/components/shared/VarianteSwatch.tsx
import { labelVarianteRow } from "@/lib/variante";

// row = linha embedada de variantes_tecido:
//   { nome_variante, codigo_variante,
//     cor: { nome, hex? }, apelido: { nome } }
export function VarianteSwatch({ row }: { row: any }) {
  const hex = row?.cor?.hex ?? null; // placeholder: coluna
                                     // hex ainda NÃO existe no banco
  return (
    <span className="inline-flex items-center gap-2">
      <span
        className="h-3 w-3 rounded-[3px] border shrink-0"
        style={{ backgroundColor: hex ?? "var(--muted)" }}
        aria-hidden
      />
      <span className="truncate">{labelVarianteRow(row)}</span>
    </span>
  );
}
labelVarianteRow (src/lib/variante.ts:32) já resolve cor base (cor.nome/cores.nome) + apelido (apelido.nome), junta com " - " e cai p/ codigo_variante → "—". Não montar o texto à mão.

DCampo editável (branco) vs derivado (cinza)

Quando usar: em formulários com mistura de entradas e valores calculados. Editável = Input/NumberInput fundo card. Derivado (não editável) = caixa bg-muted via helper CampoRO. A convenção deixa claro, à distância, o que o usuário controla.

// Derivado (calculado) — helper CampoRO
function CampoRO({ label, value }: { label: string; value: string }) {
  return (
    <div className="grid gap-1">
      <Label>{label}</Label>
      <div className="h-9 px-3 flex items-center rounded-md
                      border bg-muted text-sm tabular-nums">
        {value}
      </div>
    </div>
  );
}

GBarra de ações + container (Sheet/Dialog) + toque 44px

Padrão do sistema. Container: editar registro existente = Sheet (side=right ~70vw); criar/novo/formulário/config = Dialog. Botões: barra sticky no rodapé em TODOS os tamanhos — rodapé in-flow do modal (shrink-0 border-t com corpo flex-1 overflow-y-auto), ou <PageActionBar> (+pb-24) em página inteira. Nunca ação primária no header. Ordem fixa: Voltar (esquerda, com ArrowLeft — nunca "Cancelar"/"Fechar") · Excluir ao lado (se houver, variant="destructive" vermelho) · Salvar à direita (ml-auto). Use flex items-center gap-2, não justify-end. Header: todo form começa com <Breadcrumb> "Módulo › Tela › Entidade"; botões de imprimir no header topo-direita (indicador cai abaixo). Páginas de LISTA mantêm header + <MobileActionBar> (só-mobile). Toque ≥ 44px (max-md:h-11).

Código
